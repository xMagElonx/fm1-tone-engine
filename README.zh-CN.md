# FM-1 音色台

<sub>[English README](README.md) · 线上直接可用：<https://fm1-tone-engine.app.workbuddy.host/></sub>

浏览器里的 M-VAVE FM-1 音色引擎（M-VAVE FM1，也常写作 FM-1 / Fm1，同一台机器）。**检索、试听、说一句人话改音色、导出、写入设备。**

双击 `index.html` 即可运行。没有构建步骤，没有依赖。
写入设备那一项需要一台 FM-1；其余全部不需要硬件，也不需要网络。

「说一句人话改音色」默认走**本地词典**（离线、免费）；想让它听懂
「像老式电钢那样，但更清脆一点」这类**描述**而不只是字面词，可以把中间那层
换成大模型 —— 不需要服务器，双击打开就能直连。见 [`LLM.md`](LLM.md)。

**没时间看长文的话**：[`SHOWCASE.md`](SHOWCASE.md) 把整个项目压成一屏 ——
做过什么、怎么证明是对的、抓到过什么。

> **整个项目里唯一「此前不存在」的东西**：布局表交叉校验器
> （[`tools/tablecheck.mjs`](tools/tablecheck.mjs) + 报告
> [`LAYOUT-CROSSCHECK.md`](LAYOUT-CROSSCHECK.md)）。它用真实音色字节去验证任何一份
> 流传的 DX7 packed voice 格式表 —— 四把不需要权威的尺子，是圈内目前**独一份**的
> 工具。首跑就实测判死了一份广为流传的 AI 生成解码器：算法号在错字节、
> 128 个音色往返 0 个存活、每个音色静默丢 20 字节。

> **⚠ 硬件状态 —— 欢迎来测。** 这里的一切都能跑、有 521 项测试断言罩着，
> **但「写入设备」这条路从来没碰过一台真 FM-1。** 发出去的字节与真实抓包逐字节一致；
> 未验证的是设备拿到字节之后做什么 —— 写进哪个 bank、4104 字节的 SysEx 会不会被
> MIDI 栈截断、浏览器在本地文件下能不能拿到 MIDI 权限。如果你手上有原厂固件的
> FM-1：走 **USB**（不要走 TRS —— 长 SysEx 会溢出）测一遍大约五分钟，
> 逐步清单在 [`MIDI-WRITE.md` 第六节](MIDI-WRITE.md)；哪些验证过、哪些没有，
> 同文件第四、五节有诚实清单。测完请[开个 issue](../../issues) 告诉大家你看到了什么
> —— **失败了更要说**，阴性结果正是这个项目现在最需要的东西。

## 它能干什么

- **打开就有 32 个音色** —— 随仓库分发的原创音色库，每个都标着它在演示什么 FM 原理
- **载入** 出厂 128 个音色（4 个 bank），或拖入任意数量的标准 DX7 `.syx` 音色库
- **检索** 按音色名、来源文件、原名、Yamaha 卡带编号、算法编号搜索；按亮度排序
- **试听** 点一下就能听见。内置一台 6 算子 FM 引擎，直接在浏览器里合成，不用装插件
- **看清结构** 每个音色都画出它的**算法图**——6 个算子怎么接、谁是载波、反馈落在哪
- **导出** 单段试听为 WAV；把检索结果的前 32 个拼成一个新的 `.syx` bank
- **溯源** 出厂音色的逐槽台账：来自哪个 DX7 音色库文件、原名是什么、能不能追回 Yamaha 官方卡带
- **说一句人话改音色** 选中一个音色当锚点，输入「亮一点，尾巴拖长些」，
  它会告诉你听懂了什么、准备动哪些参数、改完什么样，**先听 A/B 再决定留不留**。
  默认解析在本机完成，不联网、不花钱；改动落在副本上，原音色一个字节都不动。
  细节与实测数字见 `NATURAL-LANGUAGE.md`
- **可接大模型（可选）** 把上面那层的中间换成大模型，就能懂描述而不只是字面词。
  直连任何 OpenAI 兼容接口，**不需要服务器**（实测过：DeepSeek、智谱会应答
  `file://` 页面那个 `null` 来源）；也可以接本机 Ollama，那样完全不花钱。
  三条设计上的硬边界：**模型碰不到字节**（它只能说「亮度 +0.45」，动哪个参数
  仍由那份过了实测断言的确定性映射算，所以它坏不了音色）；模型答非所问时
  **自动退回本地词典**并说明原因；Key 只存在你这台机器的浏览器里。见 [`LLM.md`](LLM.md)
- **写入设备** 通过 Web MIDI 把音色送进 FM-1（需要一台琴 + Chrome/Edge）。
  三道闸门：只发标准 bank dump、必须勾选确认、结果不足 32 个不放行。
  **尚未在真机上验证** —— 拿到琴之后第一步做什么，写在 `MIDI-WRITE.md` 里
- **自检** 页面一打开就跑一遍解码器审计，每一行 PASS/FAIL 都看得见

## 为什么它不是"又一个编辑器"

FM-1 这个圈子已经有一个很好的音色库工具（fm1-editor.com）和 40 多个第三方固件，
本项目**刻意不跟这两样竞争**。

它也**不是第一个把大模型接进来的东西**。2026 年 10 月，
`hunterxiong2026/fm1-felucca-editor-2026`（MIT）发布了这个方向上的第一个 LLM / Agent skill：
用自然语言驱动一台运行 **Felucca** 固件的 FM-1，做多轨编曲和参数编辑。
这里点名叫出来，是因为**差别正好就是重点** —— 诚实的说法比"AI 调 FM-1"要窄：

| | Felucca Editor Skill | 本项目 |
|---|---|---|
| 固件 | Felucca（社区替换固件，刷入有真实风险） | **原厂 V15**，出厂什么样就什么样 |
| 协议 | Felucca 自己的编辑器协议（约 111 个轨道参数 + 27 个全局） | **标准 DX7** —— 设备本来就会说的那套 |
| 需要什么 | 真机 + USB + Windows + Python + 一个空闲的 MIDI 端口 | **一样都不需要** |
| 模型产出什么 | Felucca 的参数值 | 五条轴 + 强度；字节由一份过了实测断言的映射算出 |

所以本项目占的那一格，比"AI 调 FM-1"要窄：

**用说话的办法改一台原厂、未改装 FM-1 的 DX7 音色 —— 开一个浏览器标签就行，
不需要机器、不需要安装、不需要刷固件。**

## 三层音色来源：点开就能用，同时不发不该发的东西

这两件事看着互斥 —— 不发字节，那别人 clone 下来不就是个空壳？用三层结构解开：

| 层 | 来源 | 需要什么 | 内容 |
|---|---|---|---|
| ① | `data/starter.js` | 无。随仓库分发 | 32 个原创音色（CC0），每个带设计说明 |
| ② | 上游 raw 链接 | 网络 | 128 个出厂音色，**页面在浏览器里现取现解析** |
| ③ | `data/factory.js` | 本地跑一次构建脚本 | 同上，另加 128 行来源台账 |

三层互不冲突，谁在就用谁。**关键是第 ② 层**：

> 页面上点一下按钮，浏览器自己去上游把原始字节拉下来、在内存里解析。
> 字节从头到尾没有进入这个仓库，也没有从作者手里分发出去过。

这和 `tools/fetch_ref.sh` 是同一个法律动作（提供工具，不提供内容），
但体验从"跑三条命令"变成了"点一下"。上游返回 `Access-Control-Allow-Origin: *`，
所以双击打开 `file://` 页面同样能取到。

取不到（断网、被墙、浏览器限制）就退回第 ① 层：32 个原创音色不受影响，
同时弹出一段说明告诉你本地方式怎么走。**不会静默失败。**

## 音色格式：写下来了，而且**能跑**

[`VOICE-DATA.md`](VOICE-DATA.md) 是 packed DX7 音色的逐字节布局 —— 也就是 FM-1 存储
并接受的那个格式 —— 包括格式里**没有用到**的位，以及本项目自己的解码器错过一阵子的
两个地方。这份文档是英文的，因为它本来就是写给这个圈子看的，不是写给作者自己看的。

那张表不是散文，它以**数据**的形式放在 `engine/dx7.js`（`DX7.LAYOUT`），
而 `tools/layout.mjs` 拿真实字节来验它：把表里声称的每一个位单独翻转，要求解码结果必须变；
再把表里**没有**声称的每一个位单独翻转，要求解码结果必须不变。
「声明了却没有任何人读」正是「振荡器同步永远是关」那个 bug 活下来的方式 ——
现在这条检查会直接把字节和位号点出来。

```bash
node tools/layout.mjs your-bank.syx
```

**用这个工具不需要本项目、不需要它的数据、也不需要一台 FM-1。** 如果你在写 DX7 导入器，
它会告诉你哪些字节跟格式对不上；同一份文档也照实说了格式里还有哪些部分至今未知。

`tools/layout.mjs` 判的是「你的字节符不符合这张表」。另一个问题 ——
「我照抄的那张表本身对不对」—— 归 [`tools/tablecheck.mjs`](tools/tablecheck.mjs) 和
[`LAYOUT-CROSSCHECK.md`](LAYOUT-CROSSCHECK.md)。四把不需要权威的尺子：
音色名字段自己暴露位置（全可打印的窗口只有一个）、算子块大小自己量得出来（步长 17）、
从来没为 1 过的位不是参数、同一个位不许被两条声明占用。那张把算法号放在 byte 96 的表，
四把尺子一条都过不了。

## 授权：把"能不能发"这件事查清楚了

见 **`LICENSE-AUDIT.md`**。一句话概括：

> 出厂音色的 128 个参数集，**权利链在第 1 层（Yamaha）就断了**。
> 上游仓库对这批数据声明了 CC0，但那份声明只覆盖他自己的抓包与解码，
> 并明确写了「我对音色参数本身不主张任何权利」。

所以这个仓库**不发那批字节**：

| | |
|---|---|
| ✅ 发 | 引擎代码、32 个算法的连接表、格式说明、32 个原创音色、这份审计 |
| ❌ 不发 | `ref/`、`data/factory.js`、`demo/*.wav`（都在 `.gitignore` 里） |

**区别不是形式主义**：分发是一个独立的、可被追责的行为，提供工具不是。

而 `starter/` 下的 32 个音色是本项目**从零设计**的，以 CC0 发布 —— 它不受这条限制，
所以可以随仓库自由分发。这也正是第 ① 层能存在的理由。

**本项目自己的许可证是 MIT**（见 `LICENSE`）：随便用、改、商用、二次分发，
唯一的要求是保留版权声明。理由和上一条是同一个逻辑 —— 这个仓库只发工具、
不发第三方的字节，那它自己就更应该把态度写清楚，而不是含糊过去。

## 使用与验证

**只是要用它**：双击 `index.html`。没有别的步骤。

**想拿到 128 个出厂音色**：打开页面后点「取出 FM-1 出厂音色」。
需要离线可用的话，在本地跑一次：

```bash
bash   tools/fetch_ref.sh        # 从上游取参考字节（ref/）
python tools/build_assets.py     # 重建 data/factory.js
```

**想验证整个项目**：

```bash
node   tools/verify.mjs          # ① 解码器审计（拿真实字节验）
node   tools/engine_test.mjs     # ② 试听引擎审计（算法表 + 合成结果）
node   tools/verify_starter.mjs  # ③ 随附音色库：能不能发声 / 参数是否合法
node   tools/midi_test.mjs       # ④ MIDI 层：字节对齐、发送守门、设备往返
node   tools/intent_test.mjs     # ⑤ 自然语言层：改得对不对，渲染出来量
node   tools/llm_test.mjs        # ⑥ 大模型接入层：畸形回答、失败降级、不泄漏 Key
node   tools/smoke.mjs           # ⑦ 页面端到端，五个场景
node   tools/layout.mjs          # ⑧ 音色字节布局审计（位级，可指向任何一份 bank）
node   tools/tablecheck.mjs      # ⑨ 流传的那几张布局表对不对？（量出来，别信权威）
node   tools/param_test.mjs      # ⑩ 单参数实时写入层：155 参数表、SysEx、技法宏
```

十条命令全部退出 0，共 **521 项断言**（26 + 28 + 30 + 57 + 33 + 109 + 157 + 23 + 19 + 39），可复现。

**全新 clone 上直接跑也全部退出 0。** 需要出厂音色的那几项会打印 `SKIP` 并说明
怎么把数据补上 —— 不会崩，也不会悄悄给个通过。这是刻意的：一个公开仓库的测试包
必须能在「什么都没配」的机器上跑完。

两条最要紧的断言：

- 第 ④ 条里，拿 `data/factory.js` 里那批从真机抓包重建的字节走一遍发送路径重新打包，
  要求输出与原始字节**逐字节相同** —— 证明页面发出的东西跟真实世界那份 bank 是同一串。
- 第 ⑤ 条里，说「更亮」就真的渲染 192 个音色、真的量频谱重心，要求它**一个都不许反向**；
  说「尾巴更长」就真的量包络，要求它真的拖后。**这一层的方向正确性不靠读代码判断。**
- 第 ⑥ 条里，模型的各种不听话 —— 乱码、给错轴名、按 0–100 打分、值超范围、401、
  断网、超时、明明说做不到 —— **一个都不许抛异常**，而且每条都必须落到一个说得出
  原因的结果上。另有断言专门盯「返回里不含 API Key」。
- 第 ⑦ 条里给每个场景都装了**联网守门**：本来不该联网的场景一旦真的去联网，
  会被断言当场抓住，而不是悄悄退回本地词典把问题藏起来。

**想改那 32 个音色**：

```bash
python tools/make_starter.py     # 打包 bank、starter.js、starter/README.md
node   tools/render_starter.mjs  # 渲染 starter/preview/_starter_medley.wav
```

## 试听引擎的实现边界（请务必读这段）

**它不是 DX7 的复刻，是一台能听出音色特征的近似引擎。**
要准确复刻请用 Dexed（它是免费的，而且做得更好）。这一版的目标是让你在浏览器里
**分辨**音色，不是**还原**音色。

### 已实现

| 部分 | 做法 |
|---|---|
| 算子连接 | 全部 32 个算法，含算法 4 / 6 的跨算子反馈（OP4→OP6、OP5→OP6） |
| 频率 | 比率模式（粗调 0 → 0.5，微调 +1%/级）、固定频率模式（1/10/100/1000 Hz） |
| 失谐 | ±4 音分/级（近似，DX7 的实际曲线不是线性的） |
| 包络 | 4 段：R1–R3 在按下时推进，R4 在松开后释放；**按电平跨度计时**（跨度为 0 的段几乎瞬时） |
| 电平映射 | 0.75 dB/级；电平 0 直接归零 |
| 反馈 | 一采样延迟回馈；反馈量 = (n/7)² |
| 输出 | 峰值归一化到 0.85（增益封顶 20×，免得把极安静的包络抬成噪声）+ 首尾各 3 ms 淡入淡出 |

### 未实现（会改变音色细节，不是 bug）

- **按键电平缩放**（breakpoint / 左右深度 / 左右曲线）—— 它让同一个音色在高音区变亮、低音区变暗
- **速率缩放**（rate scaling）—— 它让包络在高音区跑得更快
- **力度灵敏度** —— 预览固定用满力度
- **LFO** —— 所以颤音、震音不会出现
- **音高包络**（Pitch EG）—— 所以音头上的滑音不会出现
- **DX7 的位深与 DAC 特性** —— Dexed 用三套引擎（Modern / Mark I / OPL）在模拟这个，
  这里直接用了理想正弦

界面里的参数表会把这些字段照原样显示出来，你能看到它们，只是听不见它们。

## 算法表从哪来

32 个算法的算子连接，取自一份公开的文本化描述（LAU 邮件列表，Sean Bolton 提供，
摘自 hexter 源码），转写时保持原文的嵌套结构不变形。

**用 Yamaha 官方 DX7 操作手册的 4 条独立事实做了交叉验证，全部吻合：**

| 手册原文 | 对应 |
|---|---|
| 算法 1 的两个载波是 OP1 与 OP3 | ✓ |
| 算法 5 是 3 载波 + 3 调制器 | ✓ |
| 算法 16 是 1 载波 + 5 调制器 | ✓ |
| 算法 32 是 6 载波、无调制器 | ✓ |

另加两条全局不变量（`tools/engine_test.mjs` 里断言）：
**OP1 在全部 32 个算法里都是载波**；每个算法 6 个算子各出现一次、反馈路径恰有一条。

注意：hexter 本身是 GPL-2.0，**本项目没有使用它的代码**，只用了对硬件行为的事实性描述
（同样的内容 Yamaha 手册里也公开写着）。如果将来要引入它的实现，那就是许可证问题了。

## 过程中的十三个真问题（都改了，也留了痕）

1. **算法表漏了一层共享。** 算法 19–25 在原记法里用一个临时变量让同一个调制器
   同时喂多个载波，我转写时把表达式抄了两遍——数值上等价，结构上错了。
   是"每个算子各出现一次"这条断言把它抓出来的。

2. **量东西的尺子自己是错的。** 那段 FFT 在三个脚本里各抄了一份，
   其中两份漏掉了位反转置换，于是所有音色的"频谱重心"都落在 8–12 kHz，
   看上去像引擎把音色渲染成了白噪声。**引擎没错，是尺子错了。**
   修法是把 FFT 收成 `tools/fft.mjs` 一份，并且**给 FFT 本身加断言**。

3. **冒烟测试抓出页面会崩。** 在没有 Web Audio 的环境里，`playVoice` 直接抛异常。
   现在改成先渲染、后播放——试听结果和 WAV 导出照常可用，只是没声音。

4. **字节顺序写错，音色依然"合法"。** 生成随附音色库时，我把 EG 的 8 个值
   `(R1 L1 R2 L2 R3 L3 R4 L4)` 交错着直接切前 4 个当 rate。而 DX7 的 packed 格式是
   **先 4 个 rate、再 4 个 level**。后果很隐蔽：格式全对、校验和对、渲染不报错，
   但**每个音色的包络都不是设计的样子**——慢起音变成了"先冲一小下再掉下去"。
   揪出它的是实测数据：渲染峰值 0.387，而 0.387 恰好等于 sustain 电平 88 的振幅。
   修法是加一道 `unpack_op` 往返断言，让这类错在打包期就炸掉。

5. **工具把文件的换行改掉了。** Python 的 `write_text()` 在 Windows 上默认把
   `\n` 翻成 `\r\n`，于是我的补丁脚本把 `index.html` 整篇换行改了一遍，
   冒烟测试里的 `/<script>\n/` 立刻匹配不到。修法是在所有 Python 写入处显式传
   `newline="\n"`。**工具也会咬人，而且咬得不响。**

6. **「按槽位排序」其实是乱序。** 它被写成 `(bankLabel + slot)` 的字符串比较，
   而那是**字典序** —— 于是顺序变成 0, 1, 10, 11, …, 19, 2, 20, …，
   一个 bank 里的 32 个音色全被打乱。这个 bug 从写下那天就一直在，
   只是没人看得出来：界面上的卡片看起来很正常，导出的 bank 也一样「长得对」。
   是接入写入功能时把它揪出来的 —— 页面写进设备的 32 个音色，
   跟源 bank 对不上，才回头看见排序写错了。
   **一个新功能会照亮旧代码里你以为没问题的地方。**

7. **「振荡器同步」这个参数，从写下那天起就一直是错的。** 它被放在字节 111 的 bit4，
   而标准格式是 **bit3**。真实数据里所有取值都 ≤ 15，bit4 永远是 0 —— 于是平台
   读到的永远是「关」，界面上也一直这么显示，而实际 128 个出厂音色里有 **87 个是「开」**
   （对着 `ref/packed128.bin` 实测；byte 111 的完整取值分布见 `SHOWCASE.md`，最大值恰好是 15）。
   它整整静默了一轮：格式全对、往返全过、渲染正常。
   揪出它的是给「改造音色」补的**打包→解包往返断言** —— 127 个字节全往返一致，
   唯独 111 对不上，才回头去核标准格式。
   **先是「多出来一个位」，然后是「这个参数一直是假的」：两个 bug 藏在一处。**

8. **量东西的尺子错了三次，每次都看起来像功能坏了。** 做自然语言那一层时：
   用样本峰值位置量起音（对持续音毫无意义）；用频谱重心量亮度（FM 会把能量向两侧
   对称展开、重心反而被摊薄，而高频能量占比其实涨了 208%）；从一个固定时刻开始量
   （`BRASS 1` 的起音段长达 0.45 秒，一直在量「还没亮起来」的那一瞬）。
   三次都是尺子错了，不是被量的东西错了。修法写进了断言里：**量频谱的归量频谱，
   量包络的归量包络，而且包络一律按整段能量加权、不取固定时刻。**
   完整过程见 `NATURAL-LANGUAGE.md`。

9. **抠 JSON 抠到了模型举的那个例子。** 从模型的回答里找「第一个配平的花括号」，
   会很自然地取到它先举的例子 ——「举例 `{"foo":"bar"}`，我的建议是 `{…}`」——
   而不是它真正的答案。格式全对，解析毫不费力，结果却是错的。
   修法：把所有能配平的片段都试一遍，**优先选那个认得出来的**（带 `axes`、
   或带一个已知轴名的）。这条是写测试用例时想出来的，不是踩出来的 —— 但它值一个条目。

10. **刻度换算按整批最大值做，会把对的那个一起带坏。** 模型有时按 0–100 打分。
    我最初按整批的最大值统一换算，于是 `{"bright":0.5,"sustain":80}` 里的最大值
    是 80，一刀切成百分制之后，那个**本来完全正确的 0.5 被压成 0.005 然后丢掉了**。
    修法是逐值判断：≤1 原样、≤10 按 1–10 评分制、再大按百分比，并且把换算过这件事
    如实告诉用户。**同一个回答里混着两种刻度**是真实会发生的情况。

11. **测试里靠改全局变量模拟外部依赖，在依赖改成注入式之后会静默失效。**
    为了给大模型层做端到端测试，我把 `fetch` 改成从参数注入；结果场景 B 里那句
    `globalThis.fetch = …模拟断网` 一夜之间不再起作用 —— 它本来就在模拟一个
    页面根本不会再用的东西。揪出它的是新加的那条**联网守门**断言：
    「本来不该联网的场景，一次请求都不许发」。它直接点名了两次意料之外的请求。
    **一个断言的价值，有时不在于它验的功能，而在于它顺手照亮的那块旧地方。**

12. **一份拷贝不等于一次 clone。** 此前每一次「全新 clone 上也能跑」都是用 `tar` 把目录
    复制一份来做的 —— 而 `tar` 会原样保留行尾，于是它只是在附和这台机器，对真正的 clone
    什么也没证明。第一次真的 `git clone` 出来，`tools/smoke.mjs` 在跑第一条断言之前就崩了：
    Git for Windows 把 `core.autocrlf=true` 写在**系统级**配置里，而仓库内的设置不随 clone
    带走，于是 `index.html` 检出成 CRLF，测试里的 `/<script>\n/` 永远匹配不到。
    修法是加一个 `.gitattributes`（`* text=auto eol=lf`），它盖得住任何人的本地设置。
    **最容易复现的那套环境，最有可能骗过你。**（与第 5 条同源，只是换了一扇门进来。）

13. **打错一个名字，它变成了 `NaN`，而且一声不吭。** 写 `tools/layout.mjs` 时我把
    `DX7.SYSEX_BYTES` 打成了 `DX7.SYX_BYTES`。读一个不存在的属性得到 `undefined`，
    `4104 % undefined` 得到 `NaN`，而 `NaN === 0` 就是 `false` —— 于是分支悄悄走了另一边，
    失败在一层调用之外才浮出来，表现为一句莫明其妙的「认不出这是什么」。
    没有异常、没有警告、没有一处指向那个拼错的名字。
    修法是**用之前先确认常量**：任何一个赖以成立的数字不是正整数，工具就拒绝启动。
    **在 JavaScript 里，写错的名字不是错误，它是一个值。**
    这其实是第 5 条和第 12 条最纯粹的形态：你为了抓静默错误而写的那个检查，本身也是代码，
    它自己也可以静悄悄地错。

顺带一个副产品：网上流传较广的一张 DX7 字节对照表把算法标在第 96 字节，
**实测在第 110 字节**。这也是坚持从真实字节反推、而不是照着二手表格写代码的原因。

## 已知限制

- 试听引擎的边界见上，**不要拿它当音色设计工具**
- 随附音色库里个别设计点（如 `KICK` 的下扫）依赖音高包络，而引擎尚未实现 ——
  **数据是对的，只是浏览器里暂时听不出来**，`starter/README.md` 里已逐条标注
- 出厂音色的台账表来自上游 `docs/`（**CC BY-SA 4.0**），整表搬运需署名 + 相同方式共享
- `Dexed_cart 1.0` 的授权状态查不清，所以它只能被当作*来源*记录，不能当作*许可*使用
- 本地词典那一层只认五条轴的**字面词**；复合约束（「温暖但不要糊」里的后半句会丢）、
  以及「像老式电钢那样」这类描述，它都不懂 —— 接上大模型才懂。
  但**模型选轴的准确率还没实测**（没有真实 Key，也没拿真实模型跑过那 192 个音色）。
  验过的是**映射**：轴 → 参数 → 声音，实测一个都不许反向。边界见 `LLM.md` 第七节
- 本项目的许可证是 **MIT**；`starter/` 下的 32 个音色另行声明为 CC0。
  第三方数据的边界见 `LICENSE-AUDIT.md`
- **写入设备这一项没有真机验证过。** 代码写完、测试通过、发出的字节与真实世界
  逐字节一致 —— 但「设备收到之后写到哪里、顺序对不对」只能插上琴才知道。
  拿到琴之后第一步做什么，见 `MIDI-WRITE.md` 第六节
- 写入是不可逆的：FM-1 对**标准 DX7** 的读取请求不作答，设备里原有的音色读不出来。
  （2026-10-15 补：有一条未公开的私有命令能读回**当前音色**，见 `MIDI-WRITE.md` 5.5 ——
  但本项目没实现、也没验过，所以实际操作上这句仍然成立。）
